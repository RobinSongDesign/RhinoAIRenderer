# P3 图片编辑功能

目标：把「截图 → 生成 → 保存」的一次性流程，扩展成可以反复修改、回退、对比的编辑工作流。
前置条件：P2 全部完成。验证方式与 P2 相同（见 `phase-2-ui.md` 开头的表）。

本阶段的界面由三部分组成：

```
┌─────────────┬───────────────────────────────────────┬─────────────────────┐
│ 历史         │ 画布                                   │ 参数面板             │
│ （版本树、   │ （查看、缩放、对比、蒙版工具栏）        │ （模型、提示词、      │
│  收藏、标签） │                                       │  参考图、一键操作）   │
│ P3-T03      │ P3-T04、P3-T05                         │ P3-T06、T09、T10     │
└─────────────┴───────────────────────────────────────┴─────────────────────┘
```

批量模式保留为独立的页签，其结果同样进入历史。

## P3-T01 编辑会话模型与项目存储

**依赖**：P2-T04

### 目标

每个 Rhino 文档对应一个「项目」，项目里是一棵图片节点树；每个生成结果都记录它是怎么来的（配方）。

### 涉及文件

- `src/Chameleon.Core/Sessions/`：`ImageNode`、`NodeKind`、`Recipe`、`RecipeReference`、`EditSession`（见 `architecture.md` 6.3 节）。
- `src/Chameleon.App/Projects/`：`IProjectStore`、`DiskProjectStore`、`ProjectService`、`ProjectAssetStore`（先查项目再查缓存的资源视图）、`IProjectHistory`（`JobService` 依赖的窄接口）。
- `src/Chameleon.App/Services/SessionService.cs`：`session.*` 处理器与 `session.changed` 事件（与其他服务一致，放在 `Services/`）。

### 实现要点

- `EditSession`：节点字典、`CurrentNodeId`；操作 `AddNode`、`UpdateNode`、`DeleteNode(id, withDescendants)`（不带子孙删除时，子节点改挂到被删节点的父节点）、`GetPath(id)`（根到该节点）、`GetChildren(id)`。保持不变量：无环、父节点存在。
- `DiskProjectStore`：`projects/{projectId}/project.json` + `assets/`。保存去抖 500 毫秒，原子写入。项目资源从缓存资源库**复制**进项目目录，之后读取优先项目目录，再查缓存。
- 删除节点后，不再被任何节点或配方引用的资源文件一并删除。
- `ProjectService`：持有当前项目；`OpenProject(projectId)`；文档尚未绑定时使用一个临时项目（id 为 `unsaved-{guid}`，Rhino 退出时清理未被保存引用的临时项目）。
- `JobService` 改动：任务成功后为每张结果图调用 `ProjectService.AddNode`（`Kind` 为 `Generation` 或 `Edit`，父节点取 `GenerateParams.parentNodeId`，配方由请求参数生成），节点 id 写入 `job.updated` 的 `result.nodeIds`。
- `CaptureService` 改动：截图成功后可选地建立 `Capture` 节点（由 UI 通过 `session.addNode` 显式创建，避免批量预览截图污染历史）。
- 项目文件带 `schemaVersion`，为将来迁移留口。

### 测试

节点树操作与不变量；删除时的重挂与资源回收；项目的保存与重新载入；并发添加节点；任务成功后节点自动创建。

## P3-T02 Rhino 文档绑定

**依赖**：P3-T01、P2-T09　**执行者**：agent 编写，人在 Rhino 中验证

### 目标

打开哪个 `.3dm`，就看到哪个文档的编辑历史。

### 实现要点

- `RhinoHost` 实现 `GetActiveDocument`、`GetDocumentString`、`SetDocumentString`、`ActiveDocumentChanged`。文档字符串使用 `doc.Strings.SetString("Chameleon", "ProjectId", value)`。
- 订阅 `RhinoDoc.EndOpenDocument`、`RhinoDoc.NewDocument`、`RhinoDoc.CloseDocument`、`RhinoDoc.ActiveDocumentChanged`（macOS 可同时打开多个文档），统一转成 `ActiveDocumentChanged`，去抖 200 毫秒。
- `ProjectService` 的绑定规则：
  - 文档带 `ProjectId` 且磁盘上存在该项目 → 打开。
  - 文档带 `ProjectId` 但项目不存在（文件来自别的电脑）→ 新建同 id 的空项目。
  - 文档没有 `ProjectId` → 使用临时项目；第一次产生节点时生成正式 id、写入文档字符串、把临时项目转正。写入文档字符串会使文档变为已修改状态，这是预期行为。
- 文档另存为不改变 `ProjectId`（两个文件共享历史，可接受；在 `phase-5-backlog.md` 记一条「另存为时复制项目」）。
- 切换文档时：进行中的任务继续执行，结果写回它们提交时所属的项目，而不是当前项目。
- 发 `rhino.documentChanged` 与 `session.changed`。

### 人工验收

1. 新建文档，生成两张图，保存，关闭，重新打开：历史还在。
2. 打开另一个文档：历史切换为该文档的。
3. macOS：同时打开两个文档来回切换，历史随之切换。
4. 未保存的新文档生成图片后直接关闭不保存：不留下孤立项目（下次启动时被清理）。

## P3-T03 UI：历史面板与版本树

**依赖**：P3-T01、P2-T06

### 目标

左侧历史面板，展示当前项目的节点，支持选择、分支、删除、重跑。

### 实现要点

- `features/history/`：`sessionStore.ts`（订阅 `session.changed`）、`HistoryPanel`、`NodeCard`、`TreeView`。
- 两种视图可切换：
  - **时间线**：按时间倒序的缩略图列表，缩进表示父子关系。
  - **树**：从左到右的节点图，适合查看分支；节点多时可平移。
- 选中节点 → `session.setCurrent` → 画布显示该节点图片，参数面板载入该节点的配方（可一键「沿用这些参数」）。
- 从任意节点继续生成：结果成为该节点的子节点。P2 的「用作源图」改为「选中该节点」，不再丢失之前的结果。
- 节点操作：收藏、重命名标签、删除（提示是否连同后续版本）、「重新生成」（用相同配方再提交一次，结果作为兄弟节点）、保存、复制。
- 截图按钮的行为改为：截图后 `session.addNode({ kind: 'capture' })` 并选中。
- 导入图片：`files.pickImages` 后 `session.addNode({ kind: 'import' })`。
- 缩略图由浏览器按显示尺寸缩放原图即可；节点超过 60 个时列表做虚拟滚动。
- 空状态给出引导：先截取视口或导入图片。

### 测试

单元：`sessionStore`、树布局计算（节点坐标、分支不重叠）。端到端：截图 → 生成两次 → 时间线出现三个节点 → 选中第一个结果再生成 → 出现分支 → 删除一个节点 → 重跑配方。

## P3-T04 UI：画布查看器与前后对比

**依赖**：P2-T06

### 目标

替换 P2 的静态图片区，提供可缩放平移的画布和对比工具。

### 实现要点

- `features/canvas/`：`CanvasView`（用 `<canvas>` 自绘，不引入图形库；后续蒙版层叠加其上）、`viewport.ts`（缩放、平移、适应窗口的矩阵计算，纯函数）、`CompareSlider`。
- 交互：滚轮缩放（以指针为中心）、空格 + 拖动或中键拖动平移、双击适应窗口、`1` 键 100% 显示。触控板双指缩放与平移在 macOS 上可用。
- 高分屏：画布后备尺寸乘以 `devicePixelRatio`；缩放时使用图像平滑，放大超过 400% 时关闭平滑以看清像素。
- 对比模式：
  - **滑块**：当前节点与其父节点（或用户指定的另一节点）左右分割，拖动分割线。
  - **并排**：两个画布同步缩放平移。
  - **按住对比**：按住 `\` 键临时显示父节点。
- 尺寸不同的两张图按各自适应后的显示矩形对齐。
- 画布状态栏显示：图片尺寸、缩放比例、指针处像素坐标。
- 大图解码用 `createImageBitmap`；同一资源的位图缓存，上限按总像素数控制（约 1.5 亿像素），超出时淘汰最久未用的。

### 测试

单元：`viewport.ts` 的全部变换（缩放保持指针下的点不动、适应窗口、边界限制）。端到端：缩放后状态栏比例变化；对比滑块拖动；键盘快捷键。

## P3-T05 UI：蒙版工具

**依赖**：P3-T04

### 目标

在画布上绘制编辑区域，输出与底图同尺寸的黑白蒙版。

### 实现要点

- `features/mask/`：`maskStore.ts`、`MaskLayer`、工具实现、`MaskToolbar`。
- 蒙版以与底图同尺寸的离屏 Canvas 存储（单通道语义，白色为编辑区域）；显示时以半透明颜色叠加，颜色与不透明度可调。
- 工具：画笔、橡皮、矩形、套索（自由多边形，闭合后填充）、反选、清空。画笔与橡皮的大小可调（`[`、`]` 快捷键），笔迹用圆形笔刷沿路径插值，保证快速拖动时连续。
- 羽化：导出时对蒙版做高斯模糊（半径可调，默认 0），不影响编辑中的硬边显示。
- 撤销与重做：每次落笔记录受影响矩形的图像块，上限 50 步；`Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z`。
- 导出：`exportMask(): Promise<Blob>`（PNG，白色编辑区、黑色保留区）与 `getBounds()`（蒙版的包围矩形，空蒙版返回 `null`）。
- 也可从外部载入蒙版（P3-T07 的对象蒙版）：与当前蒙版做替换、相加或相减。
- 坐标换算复用 `viewport.ts`，蒙版始终按底图像素对齐，不受缩放影响。
- 切换节点时蒙版清空（提示未保存的蒙版将丢失）。

### 测试

单元：笔迹插值、多边形填充、包围矩形、撤销栈、相加相减（在测试环境中用 Canvas 的模拟实现或 `OffscreenCanvas`；纯几何部分与 Canvas 解耦以便测试）。端到端：画一笔后蒙版非空；撤销后为空；矩形工具的包围矩形与拖动范围一致。

## P3-T06 局部重绘

**依赖**：P3-T05、P3-T01

### 目标

只修改蒙版区域，区域之外逐像素不变。按后端能力选择两种策略之一。

### 策略

| 策略 | 适用 | 流程 |
|---|---|---|
| 原生蒙版 | `capabilities.supportsMask` 为真（OpenAI Images 格式） | 上传蒙版 → `jobs.submit` 带 `maskAssetId` → 结果再与原图按蒙版合成一次，保证区域外不变 |
| 裁剪合成 | 不支持蒙版（Gemini 格式） | 计算裁剪框 → 裁出局部图 → 以局部图为源提交生成 → 把结果缩放回裁剪框尺寸 → 按羽化后的蒙版合成回原图 → 上传合成结果作为节点图片 |

### 实现要点

- `features/inpaint/`：`cropPlanner.ts`、`compositor.ts`、`inpaintFlow.ts`。
- `cropPlanner`（纯函数）：输入蒙版包围矩形、图片尺寸、后端支持的宽高比列表；输出裁剪框。规则：包围矩形四周外扩 25%（至少 64 像素）以提供上下文；扩展到最接近的受支持宽高比；不超出图片边界（超出时平移，仍放不下则缩小外扩量）；裁剪框小于 256 像素时放大到 256。
- 裁剪合成策略下发送给模型的图片：裁剪出的局部图；另附一张标注图（局部图上以半透明高亮标出待修改区域）作为 `object` 角色参考，并在提示词中说明「只修改高亮区域，其余部分保持不变，输出不带高亮」。提示词模板集中放在 `Chameleon.Core` 的 `PromptTexts` 中，通过目录下发给 UI。
- `compositor`：把结果图绘制到裁剪框位置，以羽化蒙版为 alpha 与原图混合，导出 PNG 并 `bridge.upload`。合成结果的尺寸与原图完全一致。
- 因为最终图片由 UI 合成，这类任务提交时带 `GenerateParams.deferNode = true`，宿主不自动建节点；UI 合成后调用 `session.addNode({ kind: 'edit', recipe })`，配方里记录 `maskAssetId` 与 `editKind: 'inpaint'`。`JobService` 相应支持该开关。
- 参数面板在蒙版非空时切换为「局部重绘」模式：提示词描述的是要对该区域做什么；显示裁剪框预览。
- 失败或取消时不产生节点，蒙版保留以便重试。

### 测试

单元：`cropPlanner` 的各种边界情况（靠边、整图、极小区域、各宽高比）；`compositor` 用合成的测试图断言蒙版外像素与原图逐像素相同、蒙版中心像素来自结果图。端到端（假后端）：画蒙版 → 局部重绘 → 新节点出现，其尺寸等于原图尺寸。

## P3-T07 Rhino 对象蒙版

**依赖**：P3-T06、P2-T09、P0 的 G1 结论　**执行者**：agent 编写，人在 Rhino 中验证

### 目标

在 Rhino 里选中物体，一键得到这些物体在当前图片中的蒙版，实现「只改这面墙」「只换这把椅子的材质」。

### 实现要点

- `RhinoHost.CaptureSelectionMaskAsync`：按 P0 检查项 G1 验证过的方法实现（`spike-results.md` 中记录了采用的方案）。要求：
  - 输出尺寸等于请求尺寸；相机与截取底图时一致。
  - 选中物体的可见部分为白色，被其他物体遮挡的部分为黑色，背景为黑色。
  - 没有选中物体时返回 `null`。
  - 截取过程不改变文档（不留下临时对象、不改显示模式、不影响撤销栈）。
- 对齐的前提是相机没变。`Capture` 节点保存截图时的相机状态（`CameraState`：位置、目标、上方向、镜头、投影方式，以及它们与视口宽高比的哈希 `signature`）。UI 在截图后调用 `rhino.getCamera` 并随 `session.addNode` 存入节点；`rhino.captureSelectionMask` 同时返回当前相机状态。UI 发现签名与当前底图的来源 `Capture` 节点不一致时提示「视角已改变，蒙版可能不对齐」，并提供「恢复该视角」（`rhino.restoreCamera`）。对应的 `IRhinoHost` 成员为 `GetCameraState` 与 `RestoreCameraAsync`。
- 订阅 Rhino 的选择变化事件，去抖后发 `rhino.selectionChanged`；UI 的「使用 Rhino 选中物体作为蒙版」按钮显示当前选中数量，为 0 时禁用。
- 取回的蒙版进入 P3-T05 的蒙版层，可继续用画笔修补。
- 仅当底图是视口截图或其后代（同一相机）时提供此功能；导入的外部图片不提供。

### 人工验收

1. 选中一面墙 → 取蒙版 → 蒙版轮廓与截图中的墙重合，误差不超过 2 像素。
2. 墙前有家具遮挡 → 蒙版中家具位置为黑。
3. 转动视角后再取蒙版 → 出现视角已改变的提示；点「恢复该视角」后对齐。
4. 取蒙版前后，文档的撤销记录与显示模式没有变化。
5. Windows 与 macOS 各验证一次。

## P3-T08 多候选生成与挑选

**依赖**：P3-T03

### 目标

一次提交生成 2–4 个候选，并排比较后保留想要的。

### 实现要点

- 参数面板增加「数量」（1–4，上限取后端 `maxConcurrency` 与 4 的较小值）。
- 提交为同一 `groupId` 的 N 个独立任务（`jobs.submitBatch`，`mode: 'independent'`），父节点相同。
- 候选网格视图：N 个画布同步缩放平移；每个候选可「保留」「丢弃」；全部完成后未保留的候选节点自动标记为丢弃并从时间线折叠（可在历史面板中展开找回，删除由用户决定）。
- 账号模式下，提交前显示总点数消耗（`account.estimate` × N），P4-T09 接入。
- 部分失败时成功的候选照常显示，失败的格子显示错误与重试按钮。

### 测试

端到端：数量设为 3 → 出现三个候选 → 保留一个 → 时间线只显示保留的；其中一个注入失败时其余正常。

## P3-T09 多参考图与角色

**依赖**：P3-T03

### 目标

支持多张参考图，并标明每张的用途。

### 实现要点

- 参数面板的参考图区改为托盘：可添加多张（拖入、选择文件、从历史节点拖入），每张可设角色（风格、材质、物体）和一句备注。

- 参考图组合可保存为「参考集」（名称 + 资源 id 列表），存在项目里，便于在同一项目反复使用。

### 测试

单元：数量上限计算；`PromptComposer` 新增角色的输出。端到端：添加三张不同角色的参考图后提交，开发宿主记录到的请求中参考图数量与角色正确。

## P3-T10 一键操作

**依赖**：P3-T06

### 目标

把常用修改做成预设，用户不必写提示词。

### 预设

| 分组 | 操作 | 需要蒙版 |
|---|---|---|
| 时间 | 清晨、正午、黄昏、夜景 | 否 |
| 天气 | 晴、阴、雨、雪、雾 | 否 |
| 季节 | 春、夏、秋、冬 | 否 |
| 配景 | 添加人物、添加植被、添加车辆 | 可选（有蒙版时只在区域内添加） |
| 修改 | 移除选区内物体、替换选区材质（需填材质描述或给材质参考图） | 是 |
| 画面 | 高清放大（保持内容不变，提高到下一档尺寸）、扩图（向四周扩展画面） | 否 |

### 实现要点

- 预设定义放在 `catalog.json` 的 `quickActions`：`id`、分组、中英文名称、提示词模板、是否需要蒙版、是否需要额外输入、推荐的尺寸变化。账号模式下由服务端目录下发。
- 提示词模板都以「保持相机、构图、几何结构不变」的约束开头，约束文案复用默认系统提示词的表述。
- UI：参数面板顶部的操作菜单；需要蒙版而蒙版为空时，提示先画选区或用对象蒙版；需要额外输入的弹出小表单。
- 「扩图」：UI 先把原图放到更大的画布中央（四周留白区域生成蒙版），再走局部重绘流程；可选扩展比例与方向。
- 「高清放大」：以当前图为源，尺寸档位升一级，提示词要求不改变内容。
- 每个预设生成的节点配方里 `editKind` 记为 `quick:{id}`。

### 测试

单元：目录中每个预设的模板能正确填充；扩图的画布与蒙版计算。端到端：执行一个无蒙版预设与一个需蒙版预设。

## P3-T11 批量增强

**依赖**：P3-T03

### 目标

改进批量模式的速度与可恢复性。

### 实现要点

- 设置中开放批量模式选择：`serial`（默认，最一致）、`anchorParallel`（先渲染第一张作为锚点，其余并行，更快）、`independent`。界面上说明各自的取舍。
- 锚点可指定：默认第一项，用户可把任意已完成项设为锚点。
- 每项显示失败原因；提供「重试失败项」。
- 批量结果写入历史：每个视图的源图为 `Capture` 节点（标签为视图名），结果为其子节点。
- 批量任务进行中可以继续在单图模式工作；批量页签上显示进度徽标。
- 一致性参考数量上限可在设置中调整（`batch.maxConsistencyRefs`，默认 3）。

### 测试

端到端（假后端带延迟）：`anchorParallel` 模式下第一项完成后其余项同时进入运行状态；重试失败项只重新提交失败的。

## P3-T12 输出：剪贴板、批量导出、视口背景

**依赖**：P3-T03　**执行者**：agent 编写，视口背景部分需人在 Rhino 中验证

### 实现要点

- 复制到剪贴板：优先用浏览器的 `navigator.clipboard.write`（P0 检查项 H3）；不可用时走 `clipboard.copyImage`，由宿主用 Eto 的 `Clipboard` 写入图片。
- 批量导出：在历史面板多选节点 → `files.saveMany`；可选同时导出 `{文件名}.json`，内容为该节点的配方（提示词、模型、参数、参考图文件名），便于归档与复现。
- 导出格式：PNG、JPEG（质量可调）；可选统一缩放到指定长边。
- 设为视口背景：`rhino.setViewportWallpaper`，宿主把图片写到项目目录并设为活动视口的壁纸；提供「清除背景」。
- 保存对话框记住上次使用的目录（存入设置）。

### 人工验收

视口背景在 Windows 与 macOS 上能设置与清除；复制到剪贴板后可粘贴到常用图像软件。
